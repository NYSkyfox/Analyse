## 二、抓到的两种流量

### 1. 7777 端口 —— 教师机"频道广播"(teacherip)  ← 占 99.9%

**这是本次抓包的主体**，7296 + 4770 条全部是它。

**报文格式**：`UDP 单播/广播 → 本机:7777`，来源源端口也是 7777。
**关键结构**：**纯 JSON、无 16B cmdType 头**（第一个字节就是 `{`，偏移 0）。
（这也解释了抓包脚本那条 `cmdType=538970747(?)` 是**解析误判**——脚本按 8040 的"16B头+载荷"规则硬拆，把 JSON 开头 16 字节当成了假头。）

**完整报文字节（格式化 JSON，带 `\n` 缩进）**：
```json
{
   "channel" : 8,
   "checksum" : 630341,
   "msg_id" : "teacherip",
   "teacher_ip" : "192.168.2.200"
}
```
HEX 前缀：`7b 0a 20 20 20 22 63 68 61 6e 6e 65 6c 22 ...` = `{\n   "channel"...`

| 字段 | 含义（推断） |
|------|------|
| `msg_id` | 恒为 `"teacherip"`，消息类型标识 |
| `channel` | 教师端所属**频道号**（见下节映射） |
| `teacher_ip` | 广播该条教师的 IP，**恒等于来源 IP** |
| `checksum` | 校验/随机数，值随机波动、**不单调**（非递增序号） |

**teacher_ip == 来源IP 完全一致**（7296+4770 条全部验证，0 例外）。

### 2. 8040 端口 —— 用户"学生机对学生机发包测试"被另一学生机捕获的实证（仅 1 条）

59 号会话抓到唯一一条发到 **8040 管控主通道** 的包。**经与用户核实：这不是教师自动下发的管控，而是用户当时在机房进行的"局域网学生机对学生机发包测试"**——由另一台学生机(192.168.2.76)主动发出的探测/测试包，恰好被开着收包监听的 59 号机在 8040 捕获。因此这条记录的价值在于**实证了"A向B的8040管控注入链路可用、且包格式正确被对方收到"**，而非"捕获到老师真实下发的业务样本"。

收到的包**完整命中发包工具/逆向文档格式**：

```
16B 头: f4 01 00 00 | 00 00 00 00 | 00 00 00 00 | 5a 00 00 00
        cmdType=500(0x1f4)  f1=0  f2=0  payloadLen=90(0x5a)

载荷:   /*//{"CtrlCode":0,"apps":[],"cites":[],"keys":[],   ← ★ 该 /*// 系发包工具参照错误报告自行添加
              "sendState":1,"tipInfo":"","serverIp":""}
```

- 来源：`192.168.2.76:50642`（**随机源端口**，非 7777）——发包方学生机
- 接收方：`192.168.2.59:8040`（抓到它的学生机）
- 载荷是"**网络限制**"指令的**关闭档**（CtrlCode=0，apps/cites/keys 全部为空），与发包工具"关闭管控"档一致
- **印证/实证了**：
  1. ⚠️ **不能**据此断言 cmdType=500 载荷带 `/*//` 前缀——该包是参照错误报告构造的测试包（循环论证）；原生格式以反汇编为准：载荷 = 纯 JSON 无前缀
  2. JSON 字段集 = `CtrlCode/apps/cites/keys/sendState/tipInfo/serverIp`
  3. 发送端用**高位随机源端口**单播到 8040
  4. **学生机 A → 学生机 B 的 8040 管控注入链路可行**（包能真实跨机送达并被监听方捕获）

## 三、channel ↔ 教师 IP 的稳定映射（重要规律）

| 教师 IP | channel | 推测 |
|---------|---------|------|
| 192.168.0.200 | **2** | 频道 2 = 2^1 |
| 192.168.1.200 | **4** | 频道 4 = 2^2 |
| 192.168.2.200 | **8** | 频道 8 = 2^3 |
| 192.168.3.200 | **16** | 频道 16 = 2^4 |

**规律**：`channel = 2^(网段号+1)`。即教师按**所在 IP 网段**（.0/.1/.2/.3）被分配到不同频道位，用**位标志**表示所属频道（类似频道集合位掩码）。

> ⚠️ 说明：四台 "教师机" 都是 `.X.200`，但来自 4 个不同网段(0/1/2/3)。这不代表真有 4 台物理教师机，更可能是**一套多网段/虚拟化部署**，或教师端在多个网段都做了广播宣告。是否多台真教师、还是单教师多网卡广播，需结合机房拓扑判断（这超出纯抓包能确定的范围）。

## 四、广播节奏

- 同一教师 channel 的广播**约每 1 秒 1 条**（相邻同源广播间隔中位数 ≈ 1.0s）。
- 不同教师各自独立广播，彼此交错，所以整体看起来是多路每秒各来一条。
- 存在长间隔空洞（最长 1667s）——即测试同学在 16:xx 开抓、中途可能暂停或离开，18:00 前后又有一段。
