# 03 屏幕广播

> 本文汇总屏幕广播功能的静态分析与现场抓包实证。
> 分析日期：2026-09-15

---

## 一、传输方式

`ScreenSender.exe` 支持三种传输类型（字符串常量 `multicast` / `udpSingle` / `tcpSingle`）：

- **默认组播（multicast）** — 走 `MultiCastPort`（组播端口 7778）
- `udpSingle` — UDP 单播（跨网段）
- `tcpSingle` — TCP 单播

配套端口配置项：`MultiCastPort`、`ScreenUdpVerityPort`（屏幕 UDP 验证端口）、`OuterDataPort`（外部数据端口）。

## 二、现场抓包实证（09-12，教师机 `192.168.5.18`）

### 2.1 报文摘要

```
No.   Time      Source        Destination     Proto Len   Info
1901  120.479790 192.168.5.18  229.1.5.18      UDP   1458  8778 → 7778 Len=1416
1902  120.479878 ...           229.1.5.18      UDP   1458  8778 → 7778 Len=1416
...   （90 帧，0.12 秒内突发完成）
```

### 2.2 载荷解码

```
ff ff 00 00 | 8d 00 80 07 38 04 00 00 | 80 07 38 04 | 00 00 00 01 67 42 c0 28 da ...
   ↑2字节头      ↑ 自定义头字段                    ↑ H.264 SPS（67 42 c0 28 da）
```

后续字节可见：

- `68 ce 0f c8` → H.264 **PPS** NAL
- 明文串 `x264 - core 148 r2762 90a6` → 编码器标识

### 2.3 分析

| 项 | 观察 |
|---|---|
| 封装 | **自定义 2~16 字节头 + H.264 裸流**（非 RTP） |
| 传输 | **组播**，非单播 |
| 组播地址 | `229.1.5.18` |
| 组播规律 | `229.1.<教师IP第3段>.<教师IP第4段>` |
| TTL | 1（限制在本局域网） |
| 触发 | 用户点击"屏幕广播"时突发发送（非周期） |

## 三、技术原理

```
教师端 ScreenSender.exe：
  FFmpeg avcodec_find_encoder → H.264(x264) 编码 → Boost.Asio UDP/组播

学生端 ScreenRender.exe：
  FFmpeg avcodec_find_decoder → SDL2 渲染
```

- 编码器：`libx264-142.dll`、`avcodec-57.dll`
- 渲染：`SDL2.dll`（SDL_CreateWindow / SDL_RenderCopy / SDL_UpdateYUVTexture）
- 启动命令参数（`StudentLogic.dll`）：
  ```
  --mouse %d --protocol %s --bindip %s --bindport %d --remote %s --port %d
  --encoderType %s --quality %d --waitseconds %d --width %d --height %d
  ```

## 四、窗口化 —— 答案是「支持」

广播类型存在 **`pmgb-window`（窗口化）** 与 **`fullscreen`（全屏）** 两态：

- `MultiClient.exe`：`recv fullscreen: %d`、`normal set fullscreen`、`StreamRenderWindow.h_ckgb`
- `ScreenRender.exe`：`m_nFullScreen:%d`、`SDL_CreateWindowFrom`（窗口化渲染）
- 广播指令携带 `fullscreen` 字段，**默认全屏，指定 `pmgb-window` 类型时窗口化**

## 五、广播时的键盘锁

广播启动时通过 `KbFilter.sys` 锁键盘。日志对应关系（`MultiClient.txt` 的 `Lock.cpp` 与 `log.txt` 的 `regedit-broadcast` 时间戳一致）：

```

```
