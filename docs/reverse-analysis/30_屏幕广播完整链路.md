## 一、组件角色总览（屏幕广播闭环）

```
教师端:
  Teacher.exe (UI: DuiLib, "屏幕广播"/"窗口广播"按钮)
    → MainLogic.dll (教师逻辑核心)
        ├─ 决定广播类型 (pmgb-full / pmgb-window / pmgb-rect)   [E-3004]
        ├─ 拉起 ScreenSender.exe 做采集+编码+组播发送          [E-3001/3002]
        │     （采集区域 = 全屏 或 选中窗口矩形 left/top/w/h）
        ├─ 拉起 MultiRender.exe 做教师端自身渲染预览 (fullscreen=bool) [E-3003]
        └─ 经 8045 回环 IPC send-broadcast-type 通知本地 MMPC/学生端落地

网络 (7778 UDP 组播, TTL=1, 自定义头+H264):
  ScreenSender  →  229.1.<段>.<主机>:7778

学生端:
  MultiClient.exe (WS 客户端) 收到广播类型指令
    → FUN_0041A3B0 按 type 分发 (full/rect/window)            [E-3007/3008]
    → 存 this+0x1a0，dmt_screen_open → FUN_00419810
    → 拉起 ScreenRender.exe (#fullscreen#:1/0) 做解码+SDL2 渲染
  ScreenRender.exe
    → 按 this+0x844 (fullscreen) 选 WS_POPUP 全屏 或 窗口(屏宽×3/4)
    → 解码 H264 → SDL2 渲染
  键鼠锁 (仅全屏广播路径触发):
    鼠标锁 → MultiClient FUN_0041AE10 (自身)                  [E-3010]
    键盘锁 → MultiClient IPC MouseAndKeyBoardLock → StudentLogic → KbFilter.sys
```

## 二、教师端：类型决策（A 段核心）

### 2.1 UI → MainLogic
- "屏幕广播"按钮 / "窗口广播"按钮（UI 层 `BroadCast.xml`/`BroadCastRect.xml`）→ 调 MainLogic 导出 API → 内部确定**广播类型**与**采集区域**。
- 窗口广播额外要求选窗口：取其矩形 `left/top/width/height`（对应 ScreenSender 的 `left/top/width/height` 参数 [E-3002]）。

### 2.2 广播类型状态机 `FUN_10065860` [E-3004]
把类型字符串映射为数值 `DAT_10180000`（`in_stack_0000001c` = start 开关位，0=停/1=起）：

| 类型字符串 | start=1 数值 | start=0 数值 | 语义 |
|---|---|---|---|
| `pmgb-full` | 6 | 0 | **全屏屏幕广播** |
| `pmgb-window` | 8 | 2 | **窗口广播** |
| `pmgb-rect` | 7 | 1 | 矩形区域广播 |
| `yygb` | 9 | 3 | 影音广播 |
| `xsys` | 10 | 4 | （系统类） |
| `hpsj` | 0xb | 5 | （回屏截图类） |
| `closeall` | 0xc | — | 关闭全部广播 |

> 该数值最终经 8045 回环 IPC `send-broadcast-type`（MultiClient 侧字符串 `send-broadcast-type`@`0x4EDE10`、`broadcasttype`@`0x4EDE24`）下发，并在学生端 `FUN_0041A3B0` 用同一套 `1=full / 2=rect / else=window` 语义还原（注意：学生端判的是**简化码** `1/2/其它`，与教师端 `DAT_10180000` 的 `6/7/8` 不是同一编码，中间有一次转换〔推断〕）。

## 三、教师端：采集 + 编码 + 发送（ScreenSender）

### 3.1 采集
- `ScreenSender.exe` 用 `DisplayDataSource`（`GetDesktopWindow`/`GetDC`/`BitBlt`，符号见 E-3006 同区）抓帧。
- 采集范围由命令行 `left/top/width/height` 决定：全屏广播 = 整个桌面；窗口/矩形广播 = 指定矩形 [E-3002]。

### 3.2 编码
- FFmpeg（`avcodec-57`/`libx264-142`），`encoderType=H264`；编码器标识 `x264 - core 148 r2762 90a6`（抓包明文）。

### 3.3 ScreenSender 命令行（`FUN_10073280` 拼接，[E-3002]）
```
"ScreenSender.exe" "{#remote#:<组播组或目标IP>,#port#:N,#local#:<本机IP>,
  #encoderType#:H264,#dataSource#:display,#transferType#:<multicast|udpSingle|tcpSingle>,
  #verfityPort#:N,#quality#:N,#mouse#:N,#outer_port#:N,#host#:<IP>,
  #waitseconds#:N,#extendString#:"",#left#:X,#top#:Y,#width#:W,#height#:H}"
```
**关键**：
- **`fullscreen` 不在 ScreenSender 参数里**——全屏/窗口的区分不在采集侧，而在**类型协议**（§2.2）与学生端渲染（§4）。
- `left/top/width/height` = 采集矩形（窗口广播取选中窗口矩形）。
- `transferType` 决定组播/单播（§6）。
- `remote` 即组播组地址（`229.1.<段>.<主机>`）或单播目标，由 MainLogic 依据本机 IP 推导后传入（ScreenSender 自身不构造，[E-3006]）。

### 3.4 教师端渲染预览（MultiRender）[E-3003]
`FUN_10072940` 拉起 `MultiRender.exe`，参数：`teacher_ip/remote/port/local/decoderName/des/appType/verityPort/controler_port/controler_host/fullscreen`。其中 **`fullscreen` = `(in_stack_0000001c != 0)`**（bool）。这是**教师本机**看自己广播效果的渲染进程，与学生端无关。

## 四、学生端：接收 + 分发 + 渲染

### 4.1 广播类型分发 `FUN_0041A3B0`（MultiClient，[E-3007/3008]）
```c
// 反编译 25813 行
FUN_00419a00();                       // 前置
*(int*)(this+0x1a0) = type;           // type: 1=full / 2=rect / else=window
if (type == 1)      { log "pmgb-full";   FUN_004197a0(); }
else if (type == 2) { log "pmgb-rect";   FUN_004197a0(); }
else                { log "pmgb-window"; FUN_004197a0(); }
FUN_00418ed0(0);
if (*(char*)(this+0x110) == 0) {      // 首次
    log "dmt_screen_open";
    FUN_00419810();                     // 拉起/打开 ScreenRender
    ...
}
```
**重要修正**：早期报告称"全屏广播与窗口广播是两条独立代码路径"。本轮 Ghidra 显示，**三种类型在同一函数 `FUN_0041A3B0` 内按 `type` 数值分支，且都调用同一个 `FUN_004197a0`**（屏幕打开例程），类型仅存 `this+0x1a0`。全屏/窗口的**实际差异体现在**：① 启动 ScreenRender 时 `#fullscreen#` 传 1 还是 0；② 桌面切换（全屏切 `this+0x108` 黑桌面 / 窗口留当前桌面，§4.3.3）；③ 鼠标锁（`iVar5==1` 才锁，§5.2）。

> 注（与 §5 纠偏一致）：键鼠锁**不是**"`0x18500` 子函数只在全屏广播被调用"——`0x18500`（`FUN_00419100`）实为 init 清理，鼠标锁运行时由命令处理器 `FUN_0042b8c0` 的 `iVar5` 分支门控（§5.2）。"独立路径"表述对渲染主体与锁均不成立。〔已修正，置信度高〕

### 4.2 渲染（ScreenRender.exe）
- 命令行 `#fullscreen#:N`（N=1 全屏 / 0 窗口 / 2 窗口缩放）→ 存 `this+0x844`（写点 off `0x1BDA9`，读 `[ebp+0x58]`）。
- `this+0x844=1` → `WS_POPUP` 全屏无边框；`=0` → 窗口，尺寸 **屏宽 × 3/4**（硬编码）。
- 解码：FFmpeg `avcodec_decode_video2`（H264）；渲染：SDL2（`SDL_UpdateYUVTexture/RenderCopy/RenderPresent`）。
- 组播组号/端口由 MultiClient 经 `#remote#`/`#port#` 传入（ScreenRender 不构造 229，[E-3009]）。

### 4.3 NetTeachingDesktop 桌面生命周期（创建 + 5 处切换）

全屏屏幕广播的核心机制是**切换到专用 Win32 桌面** `NetTeachingDesktop`。该桌面在**学生端启动时预建**，全屏广播才切入；它由 `CreateDesktopA` 新建、无 explorer/进程驻留 → **纯黑**。以下三成员 + 创建链路 + 全部 5 处 `SwitchDesktop` 调用点，均 Ghidra 字节级核实（`multicl_x86.txt` 行号）。

#### 4.3.1 三个核心成员（MultiClient 全局对象 `this` = `FUN_0042fa70()`）

| 偏移 | 类型 | 语义 |
|---|---|---|
| `this+0x108` | `HDESK` | **`NetTeachingDesktop` 句柄**（纯黑教学桌面） |
| `this+0x10c` | `HDESK` | **原桌面句柄**（广播前所在桌面，用于切回） |
| `this+0x110` | `char` | **桌面切换总闸**（=1 启用 / =0 禁用），所有 `SwitchDesktop` 前置守卫 |

#### 4.3.5 两项纠偏（本轮字节级坐实，修正此前推断）

**纠偏 A — `this+0x110` 的真实语义：TSpace 远程接入检测，非桌面归属**

此前推断"`FUN_00415d30` 判断当前桌面是否 ∈ {Default, Winlogon, NetTeachingDesktop}"——**错误**。`FUN_00415d30`（Ghidra 22168–22235）实际读 **`C:\Program Files\SPICE Guest Tools\tspace_connect_status.ini`** 的 `[connect_status]action` 是否 `== "connect_created"`（`GetPrivateProfileStringW` 22212），判断**学生机是否经 TSpace/SPICE（RD 网关）接入**：

```c
this+0x110 = (FUN_00415d30() == 0) ? 1 : 0;    // 14746-48
```

- **本地/物理学生机**（TSpace 未连）→ `this+0x110=1` → 桌面切换**启用**
- **TSpace 远程接入的学生机**（已连）→ `this+0x110=0` → 桌面切换**禁用**（远程桌面会话下切 Win32 桌面会破坏会话，故关闭）

这才是 `this+0x110` 作为"所有 SwitchDesktop 总闸"的设计意图。

**纠偏 B — 停止广播的命令码是 `0x1d`/`0x1f`，不是 `0x7e`**

`FUN_0041aac0`（stopMulticast）三处调用者全部定位：

| 调用点（行号） | 命令分支 | 语义 |
|---|---|---|
| 42380（随后 42391 调 `FUN_0041a3b0`） | `FUN_00415c00()` 校验为真，日志 `[DataLogic][StartCheckDesktop][FullScreen][%d]` | **启动全屏广播**：先 stop 旧再 start 新 |
| 43108 | `cmd ∈ {0x1d,0x1f}` 且 `iVar5==1` | **停止全屏广播** |
| 43155 | `cmd ∈ {0x1d,0x1f}` 且 `iVar5==2` | **停止矩形广播** |

而 `cmd=0x7e`（`FUN_0042b8c0` 42798–42814）的真实职责是 **MIRCOICON 状态 + 锁开关**：`this+0x54=iVar5`（日志 `id == MIRCOICON %d`），按 `this+0x54/0x34/0x5c/0x5d` 调 `FUN_0042db00(1/0)` 设锁——**不碰桌面、不 stop/start 组播**。

**修正后的命令→动作映射**（`FUN_0042b8c0`，off `0x2ACC0`）：

| 命令码 | 动作 | 桌面操作 |
|---|---|---|
| `0x2c` | 启动广播（`msg[4:8]`=fullscreen 值） | ① 切黑桌面（全屏）/ ② 留当前（窗口） |
| `0x1d` / `0x1f` | **停止广播**（`iVar5=1/2` 区分全屏/矩形） | ③ `stopMulticast` 切回 `this+0x10c` |
| `0x7e` | MIRCOICON 状态 + 锁开关 | 无 |
| `0x81` | RegisterType（含 BARRAGE 弹幕等） | 弹幕分支 `FUN_0042e4a0` 间接涉及 |
| `0x82` | 其它 | — |

> 取当前桌面名函数 `FUN_004165f0`（Ghidra 22603–22621）：`OpenInputDesktop → GetUserObjectInformationW(hdesk, UOI_NAME, buf, 0x104)`，供 ③④ 的"是否 ≠ NetTeachingDesktop"判断。

## 五、学生端：键鼠锁（仅全屏广播路径）[E-3010]

### 5.1 两条锁的执行器
- **鼠标锁**：MultiClient 自身执行，执行器 `FUN_0041AE10`（off `0x1A210`）。由 `FUN_0042db00(N)` 构造 JSON `{"lock":N}` → `FUN_0042fa70()`（全局对象）+ `FUN_0041ae10()` 触发。
- **键盘锁**：MultiClient 经回环 IPC `MouseAndKeyBoardLock`（off `0x188D1`）→ StudentLogic `FUN_10074810` → `LockKeyboard.dll` → IOCTL `KbFilter.sys`（x64 内核驱动）。

### 5.2 运行时触发（全屏 vs 窗口）——纠偏后模型
- **鼠标锁已字节级坐实由 fullscreen 值 `iVar5` 门控**：命令处理器 `FUN_0042b8c0`（off `0x2ACC0`）cmd=0x2c 分支 `0x2B257: cmp [ebp-0x450],1; jne 0x2B26F; push 1; call 0x2CF00`——`iVar5==1`（全屏）才 `call 0x2CF00`（→`FUN_0042db00(1)` 锁），否则 `FUN_0042db00(0)` 解锁。
- 因此"全屏锁 / 窗口不锁"对**鼠标锁**成立，且**受 `fullscreen` 值直接门控**（这正是 Patch 16 单点方案的依据，见 §4.3.5 + Patch_Docs/16）。

> 纠偏：早期表述"键鼠锁不受 fullscreen 字段门控，而由是否走全屏广播路径（0x18500）决定"有误。`FUN_00419100`（off `0x18500`）实为 **init 清理**（非"分发器"，由 init `FUN_0040f790` 末尾调用，内含两次 `FUN_0041ae10` 设鼠标锁初始态 + 键盘锁 IPC 初始化），鼠标锁的**运行时**触发在命令处理器 `FUN_0042b8c0` 的 `iVar5` 分支，非 0x18500。

### 5.3 待确认
- **键盘锁的运行时门控**本轮未单独反汇编坐实到 `iVar5` 级别：前轮（E-3010）把 `MouseAndKeyBoardLock` IPC 归在 `FUN_00419100`（off `0x18500`，init 清理）内。键盘锁是"每次全屏广播运行时由 iVar5 触发（同鼠标锁）"还是"仅 init 设初始态"——**影响 Patch 16 能否完全免键盘锁**，列为实机验证关键项（§九-6）。

**为何键盘锁不在 MultiClient 直接执行**：`KbFilter.sys`/`KbDriver.exe` 为 x64，`LockKeyboard.dll` 需经 IOCTL 操作 x64 驱动；集中在 StudentLogic（Student.exe 宿主）统一执行便于管理锁生命周期（异常恢复，避免 MultiClient 崩溃致键盘锁死）；职责分离（MultiClient"说"、StudentLogic"做"）。

## 八、核心结论（回答"能否把教师全屏广播转为学生窗口广播"）

> 本章为**纠偏后**结论（与 §4.3 / §5 一致）。早期"全屏与窗口是两条独立路径、锁由 0x18500 路径决定"的模型已废弃。

1. **全屏/窗口的区分是"类型协议"，但学生端接收侧收敛到唯一驱动源 `iVar5`。** 类型在教师端 `FUN_10065860` 决策（[E-3004]）→ 下发 → 学生端命令处理器 `FUN_0042b8c0`（off `0x2ACC0`）读 `msg[4:8]` 为 `iVar5`（fullscreen 值：1=全屏 / 2=矩形 / 其它=窗口）。**这一个 `iVar5` 同时门控三件事**：
   - ① 桌面切换（全屏→切 `this+0x108` 黑桌面；窗口→留当前桌面，§4.3.3）；
   - ② 鼠标锁（`iVar5==1` 才 `call 0x2CF00` 锁，§5.2）；
   - ③ ScreenRender 渲染模式（`#fullscreen#`=1 全屏 / 0 窗口，§4.2）。

2. **因此"把全屏转窗口"在源头单点即可达成，不需要分别改桌面/锁/渲染三处。** 旧模型（§五早期版）认为"单点翻转 fullscreen 只能改渲染、改不了锁，锁由 0x18500 路径决定"——**对鼠标锁而言错误**：鼠标锁由 `iVar5` 直接门控（§5.2 字节级坐实），强制 `iVar5=0` 后 ①②③ 自动全部跟随窗口语义。

3. **单点 patch 已字节级定稿并落盘（Patch 16，`Patch_Docs/16`）。** 在 `FUN_0042b8c0` cmd=0x2c 分支的文件偏移 `0x2B18B` 处，把读取 `msg[4:8]` 的 `mov edx,[ebp-0x21c]` 改为 `xor edx,edx`（12 字节等长替换，锚点全文件唯一 count=1），强制 `iVar5=0`。教师端无论发全屏/窗口/矩形，学生端统一走窗口分支（真实桌面 + 可缩放窗口 + 免鼠标锁）。**不再需要 `0x18500` 全函数副作用评估**——因为锁不靠 0x18500 路径，而靠 `iVar5`。
   - 工具侧已提供**文件 patch**（「修补」第 7 项）与**内存 patch**（「内存 Patch」⑯，RVA `0x2BD8B`）两条等价通道。

4. **与旧三点方案（Patch 01 窗口化 + ⑭键盘锁 + ⑮鼠标锁）的取舍**：
   - 旧三点只改"渲染"（Patch 01）+ 各 NOP 一个锁函数，**不解决桌面切换**（用户实测"窗口化后纯黑背景"即此因）；
   - Patch 16 单点从源头清零 `iVar5`，**一并解决桌面/鼠标锁/渲染**，且天然免锁；
   - **唯一待实机确认**：键盘锁是否也随 `iVar5=0` 解除（§5.3）。若实机发现全屏转窗口后键盘仍被锁，则键盘锁走独立门控，需叠加 ⑭（键盘锁 patch）。这是 Patch 16 实机验证的关键观察项。
