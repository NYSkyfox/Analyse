## 二、字节级 IDL

### 2.1 TCP/9003 帧头（通用，所有 cmdType 共用）

```
偏移  长度  字段        类型      字节序  说明
0x00  4     total_len   uint32  LE      = 16 + body_len（本帧除自身外的字节数）
0x04  4     cmdType     uint32  LE      命令类型（见 §一 目录表）
0x08  4     u3          uint32  LE      第3字段（0x2B 帧恒为 0x40；其余多为 0）
0x0C  4     u4          uint32  LE      保留（观测恒为 0）
0x10  4     body_len    uint32  LE      正文长度（= total_len - 16）
0x14  ...   body        byte[]  -       正文（编码因 cmdType 而异）
```

**约束**：
- `total_len = 16 + body_len`（恒等式，抓包 100% 验证）
- 线上实际字节 = `4 + total_len`（4 字节长度前缀 + body）
- 一个 TCP segment 可包含**多帧**（抓包实证：828B 段含 5 帧）
- 无序列号、无 CRC、无加密

**证据**：
- E-001: tshark t=30.736s `38000000 18000000 00000000 00000000 00000000` → 4+56=60B ✓
- E-006: tshark t=35.730s `4d040000 2b000000 40000000 00000000 3d040000` → 4+1101=1105B ✓
- 多帧: tshark t=30.855s 单段 828B = 371+56+156+155+70 ✓

**checksum 算法**（`FUN_1004c380` main@74790）：

```python
def gen_checksum():
    """6位奇偶位锁定随机数"""
    result = 0
    for i in range(6):
        result = result * 10
        d = rand() & 3  # 0..3
        if i % 2 == 1:  # 奇数位 (1,3,5)
            result += 1 + d * 2  # ∈ {1,3,5,7}
        else:            # 偶数位 (0,2,4)
            result += d * 2       # ∈ {0,2,4,6}
    return str(result).zfill(6)  # JSON 序列化时前导零丢失
```

**测试向量**（抓包实证）：
| checksum | 偶数位 | 奇数位 | 验证 |
|---|---|---|---|
| `36301` → `036301` | 0,6,0 | 3,3,1 | ✓ |
| `236307` | 2,6,0 | 3,3,7 | ✓ |
| `36761` → `036761` | 0,6,6 | 3,7,1 | ✓ |
| `636301` | 6,6,0 | 3,3,1 | ✓ |

**关键状态转移**：

## 四、握手/鉴权/版本协商

### 4.1 鉴权：**无**

- 无挑战-响应
- 无密钥交换
- 无签名/校验和（帧级）
- 学生 connect(9003) 后直接发 0x06 即可注册
- 唯一"身份"= IP + MAC（在 0x06 路径字符串中，但**不校验**）

**置信度**：事实（抓包 + 反编译均无鉴权逻辑）

### 4.2 版本协商：**无**

- 无版本号字段
- 无能力位
- 兼容规则：未知（**未验证**）

### 4.3 发现机制（替代"协商"）

学生通过 7777 广播发现教师，匹配 `channel` 字段（= 2^频道号）。学生只连接与自身频道匹配的 `teacher_ip`。

## 五、可靠性机制

### 5.1 序号规则：**无**

- 帧无序列号
- JPEG 上报帧无帧序号（仅靠时间顺序）

### 5.2 ACK/NACK：**无显式 ACK**

- 0x11/0x69 空载帧可能是隐式 ACK（**推断**，未验证）
- 无 NACK 机制

### 5.3 重传：**无应用层重传**

- 依赖 TCP 自身可靠性
- UDP 通道（7777/7771）无重传（best-effort）

### 5.4 分片/重组

- TCP 通道：接收端有拆帧状态机（§2.1 帧头 total_len 驱动），支持一个 TCP segment 内多帧
- UDP 通道：单包即一条消息，无分片

### 5.5 重复/乱序处理：**无**

- TCP 保证有序，无额外处理
- 重复帧会被重复处理（如重复心跳 = 无害）

```python
def read_frame(sock):
    """两段式读帧（与原版 FUN_1009bed0→FUN_1009bcb0→FUN_1009bb90 对称）"""
    header4 = recv_exact(sock, 4)
    total_len = struct.unpack('<I', header4)[0]
    body = recv_exact(sock, total_len)
    cmdType, u3, u4, body_len = struct.unpack('<IIII', body[:16])
    assert total_len == 16 + body_len
    return Frame(cmdType, u3, u4, body[16:])

def send_frame(sock, cmdType, u3, u4, payload):
    body_len = len(payload)
    total_len = 16 + body_len
    frame = struct.pack('<IIIIII', total_len, cmdType, u3, u4, body_len) + payload
    # 长度前缀 + body
    sock.sendall(struct.pack('<I', total_len) + body)
```
