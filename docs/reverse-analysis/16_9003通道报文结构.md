## 三、报文结构

### 3.1 帧头：4 字节长度前缀 + 16 字节定长头（小端序）

```
偏移  长度  字段        含义
0x00  4     total_len   ★ 长度前缀 = 16 + body_len（即"除自身外本帧字节数"）
0x04  4     cmdType     命令类型
0x08  4     u3          第 3 字段（0x0C / 0x0D / 0x2D 为 0；0x59 / 0x2B 为 0x40，含义待定）
0x0C  4     u4          保留（观测恒为 0）
0x10  4     body_len    正文长度（0x0D 下发观测为 0，接收端不依赖；0x0C / 0x2B / 0x2D 为实际正文长度）
0x14  ...   body        正文（通常 UTF-16LE）
```

> ★ **关键（抓包 + 反编译双向坐实）**：`total_len` 字段值 = `16 + 正文长度`，**不是** `20 + 正文长度`。
> 线上实际字节 = 4(长度前缀) + 16(定长头) + 正文，即 `4 + total_len`。
> 接收端是**两段式异步读**：先读 4 字节长度前缀 → 按 `total_len` 值分配/扩容缓冲 → 再读体（mainlogic `FUN_1009bed0 → FUN_1009bcb0 → FUN_1009bb90`，详见 [25 号 §二](./25_教师端崩溃与假卡死机理.md)）。
> 正文（body，= 16B 定长头 + 载荷）整体入队后，`FUN_1005ed80` 按 `body[0]=cmdType`、`body+0x0C=body_len`、`body+0x10=载荷` 解包。
>
> 实测对照（2026-09-15 抓包线上字节）：
>
> | 报文 | 线上实际字节 | total_len 字段 | 正文长度 |

> | 黑屏开启 | 44 | `0x28`(40) | 24 |
> | 黑屏解除 | 28 | `0x18`(24) | 8 |

## 八、连接方向与调用链（2026-10-23 本轮 Ghidra 坐实）

### 8.1 方向

- **学生连教师**：教师端 `Listen(9003)`，学生端 `Connect(教师IP:9003)`（09-14 抓包 `192.168.1.200:9003 ↔ 192.168.1.50:49741`，固定端=教师）。
- `9003 = ConnectPort`，读取点 main@94603（存 `param_1+0x58`）。

### 8.2 网络模型：boost::asio 异步事件循环（2026-10-23 二版坐实）

9003 主连接**不**是经典的 `socket→bind→listen→accept→recv 死循环` 同步模型，而是由 **`CMainLogic`（MainLogic.dll）的 boost::asio `io_context` 事件循环**统一驱动（`CMainLogic`/`TeacherImplDefines` 符号计数 18，mainlogic 模块）。

**服务器创建链（本轮逐字节坐实，见 [25 号 §一/§二](./25_教师端崩溃与假卡死机理.md)）**：

```
Load() 导出函数 (main@19810)
  └→ FUN_10064990(&DAT_1018faa0) (main@98985)     ← 逻辑对象初始化
       ├ this+0x30/0x34/0x38 = 0                    (main@99070-99074)  ← 三个 asio 服务器指针
       ├ *(this+0x3c) = 端口（外部栈参数传入）       (main@99078)
       ├ FUN_1005e5e0(this)                          (main@99085)       ← 读 core.conf（ConnectPort→this+0x58 main@94603）
       └ FUN_1002fa20/fa80(this+0x18/1c/20, FUN_100712d0)  (main@99095-99105)
            ← ★ 注册"事件回调"，服务器对象此刻尚未创建

FUN_100712d0(param_1=端口, param_2) (main@106511)  ← 事件触发时才执行
  ├ param_1==0x232c(9004) → FUN_100408c0(...,0x232c) + FUN_1009dac0 → this+0x38
  ├ param_2==0             → FUN_100408c0(...,(u16)param_1) + FUN_1009dac0 → this+0x30  ← 主 9003 服务器
  └ else                   → 同上 → this+0x34

FUN_1009dac0 (main@147654) → FUN_1009cbd0 (main@146761)  ← asio acceptor 封装
  ├ FUN_10090b20  (open)
  ├ FUN_1009d850  (set_option)
  ├ FUN_1009f8d0  (bind)
  └ FUN_100a03f0  (listen backlog=0x7fffffff)   main@146863
```

**每连接的两段式异步读（拆帧状态机，本轮坐实）**：

```
FUN_1009bed0 (main@146027)     ← 发起读 4 字节长度前缀（缓冲=&this+0x4c，len=4）
  └ 完成回调 FUN_1009bcb0 (main@145908)
       ├ 失败 → 日志 "ReadedHeader error:%s" → 断连
       └ 成功 → FUN_1009bb40(this+0x50, total_len) (main@145806)   ← 按 total_len 扩容（operator new，攻击者可控长度！）
              → 发起读 total_len 字节（缓冲=新分配块，len=total_len）
  └ 读体完成回调 FUN_1009bb90 (main@145872)
       ├ 失败 → 日志 "ReadedBody error:%s" → 断连
       └ 成功 → FUN_1009de60(this+0x74, buf, total_len) (main@147863)   ← 剥掉 4B 长度前缀后入队
              → FUN_1009bed0 继续下一帧
定时器 id=1（10ms）FUN_10067fc0 (main@100952)
  └ 从 this+0x30 队列每次 ≤60 条取 body → FUN_1005ed80 (main@94794)
       └ body[0]=cmdType / body+0x0C=body_len / body+0x10=载荷 → 按 cmdType 分发（17 个分支）
```

**辅助符号（本轮命中）**：

```
WSASocketW                main@140376（socket 创建封装 FUN_10095f00）
  └ setsockopt(0x29,0x1b) main@140388
WSARecv 接收封装           main@140633 / 135855
boost::asio io_context / strand / coroutines   main@63543-63607
命令分发 = boost::signals2::signal<void(TeacherImplDefines::Command)>   main@61454/67834/71357
  └ CMainLogic::OnCommand(Command)  按命令路由
```

> acceptor/strand/coroutine 被 asio 模板内联，`grep listen()/accept()` 几乎零命中。9003 的 acceptor 归属 = `FUN_100712d0` 创建的 `this+0x30`，已在本节坐实；**触发该回调的事件**（何时从"未监听"转为"监听"）仍是未验证项，也是"第一次 10061"的根源（见 [25 号 §七](./25_教师端崩溃与假卡死机理.md)）。
> 学生端 StudentLogic.dll 侧对称（connect + 收帧 + 回执），连接建立后由同一 asio 模型管理。
