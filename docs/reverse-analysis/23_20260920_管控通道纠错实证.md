# 23 · 2026-09-20 抓包：行为管控通道纠错实证

> 本文记录 **2026-09-20 学校机房抓包**（教师 `.200` → 学生 `.57`）对"行为管控/网络限制通道"的**决定性纠错**：
> 此前 [02 号](./02_行为管控指令.md) 基于静态分析推断"行为管控走 `udp/8040`"，本抓包**实测推翻**该结论——
> 网络限制等管控指令走 **`tcp/9003`** 的登录/心跳会话，且 **CtrlCode 必带 `0xBC` 高位**。
>
> 分析日期：2026-09-20 · 数据来源：`9.20抓包/easytshark_2026-09-20_16-56-05.pcap`（37MB，50633 包，主证据）
> 交叉验证：教师端/学生端 Ghidra 反编译存档

---

## 一、纠错结论（一句话）

| 项 | 旧结论（02 号·静态） | 新结论（09-20·抓包+代码双重实测） |
|---|---|---|
| 管控下发通道 | `udp/8040`（`UdpMessageControllerPort`） | **`tcp/9003`** 登录/心跳会话 |
| CtrlCode 取值 | `1` / `0x10` / `0x100`…（低位裸值） | **必带 `0xBC` 高位**：实际下发 `0xBC011111`，停止 `0xBC000000` |
| 8040 角色 | 管控接收端口 | 配置**声明值**；本系统管控运行时不走 8040 |

> ⚠ 本条同时解释了"自研 8040 CtrlCode 工具无效果"：① 发错通道（8040 vs 9003）② 缺 `0xBC` 高位（被学生端丢弃）。

## 二、会话与角色（实测）

| 角色 | IP | 端口 |
|---|---|---|
| 教师端 | `192.168.1.200` | `9003`（固定监听） |
| 学生端 | `192.168.1.57` | `52524`（临时端口连入） |

> 注意：与 09-14/09-15 那批（`.57` 教师 / `.58` 学生）角色相反，本批 `.57` 是学生。

### 2.1 端口流量分布（实测·全端口统计）

| 端口 | 协议 | 条数 | 定性 |
|---|---|---|---|
| **8040** | udp | **0** | 无流量 |
| **8045** | udp | **0** | 无流量 |
| 9003 | tcp | 34 / 30（双向） | **管控主信道** |
| 8778→7778 | udp | 23367 | 组播教学/屏幕流（高熵） |
| 7777 | udp | 195 | 多教师机 `teacherip` JSON 广播 |
| 7771 | udp | 5407 | 多教师机心跳 |
| 443/80 | tcp | 多 | 学生机业务流量（限制后衰减） |

> **8040/8045 UDP 全程 0 帧**为铁证，直接否定"管控走 8040"。

## 三、决定性帧：848 字节"登录/初始化"包（实测全解）

时间线：学生端 `+84.0s` 建立 9003 连接（SYN/SYN-ACK）→ 教师端 `+85.0s` 下发 **848 字节**包。
该包**打包 4 条子记录**，每条 = **40 字节二进制头 + JSON 载荷**（同一 TCP 段内串行）。

### 3.1 子记录帧结构（实测字节偏移）

```
偏移  长度  内容
0x00  6     魔数 23 2b cd 2c 40 2c
0x06  2     0x40 0x2c（常量）
0x08  ...   序号 / 校验 / 类型 / 长度等（逐字节语义〔推断〕，未逐字段坐实）
0x24  4     JSON 载荷长度（u32 LE）
0x28  ...   JSON 载荷（编码**混用**：UTF-8 与 UTF-16LE）
```

> 子记录头 40 字节中，除"魔数"与"JSON 长度（偏移 0x24）"可实测确认外，
> 中间字段语义为〔推断〕，需运行态/更多样本进一步定位。

### 3.2 四条子记录内容（实测）

**① 教学配置**（UTF-8）
```json
{
  "assist_ip" : "192.168.1.200",
  "controller_port" : 8040,
  "fileTransferPort" : 8555,
  "general_education" : 0,
  "home_work_server_ip" : "0.0.0.0",
  "ioControlLevel" : 0,
  "local_time" : "/2026/9/20/0/16/54/47/169/",
  "lockedAfterNetBroken" : 0,
  "screenUdpVerityPort" : 7788,
  "transferType" : "multicast",
  "waitseconds" : 80
}
```

**② 行为管控 / 网络限制（关键）**（UTF-8）
```json
{
  "CtrlCode" : -1140780783,      // = 0xBC011111
  "sendState" : 1,
  "serverIp" : "192.168.1.200",
  "tipInfo" : "网页已经被拦截，请不要搜索限制内容!"   // GBK
}
```

**③ 学生机标识**（UTF-8）
```json
{ "autosign" : true, "ip" : "192.168.1.57", "mac" : "",
  "name" : "", "pcname" : "", "shownum" : true, "stunum" : "" }
```

**④ 文件限制**（UTF-16LE）
```json
{ "LimitFileSize" : 0 }
```

> 同段另见独立帧 `{"enable":1}`（UTF-16LE，教师→学生，`+84/77s`）——疑为"网络限制开关"层，
> 与 ②的 CtrlCode"明细"层并存。二者关系〔推断〕，待"解除限制"对照帧坐实。
>
> ✅ **2026-09-22 补记**：9.22 抓包1 实测抓到"解除限制"对照帧——教师于 t=144.5s 下发独立帧 `{"CtrlCode":-1140850688}`（= `0xBC000000`），**7 s 后学生机新出网连接恢复**，随后 t=162.8s 会话重建时教师又补发完整限制包。详见 [9.22 总览 §8](../9.22抓包/总览与结论.md) 与 [抓包1 未过滤 §3.1](../9.22抓包/抓包1_教师机192.168.1.200/未过滤.pcapng.md)，本文未决项 3 闭环。

## 四、CtrlCode 位分析（实测值）

| 值 | 十六进制 | 含义 |
|---|---|---|
| **实际下发** `-1140780783` | `0xBC011111` | 高标志 `0xBC000000` + 限制位 `0x00011111` |
| **停止/清除** `-1140850688` | `0xBC000000` | 只留高标志，限制位全清 |

`0x00011111` 展开（对照 02 号位定义）：

| 位 | 值 | 管控项 | 本次是否置位 |
|---|---|---|---|
| bit0 | 0x01 | 网络禁用 | ✅ |
| bit4 | 0x10 | 应用禁用 | ✅ |
| bit8 | 0x100 | USB 禁用(变体1) | ✅ |
| bit12 | 0x1000 | USB 禁用(变体2) | ✅ |
| bit16 | 0x10000 | USB 禁用(变体3) | ✅ |
| bit1 | 0x02 | 键盘过滤 | ❌ |

> **`0xBC` 高位 = 必备标志**：实际值与停止值**共有**该前缀；自研工具此前发的 `0x01`（缺高位）被学生端丢弃。

## 五、代码侧实锤（交叉验证，对应 848 字节帧）

### 5.1 教师端（组装 + 发送）

| 函数 | 作用 |
|---|---|
| `Teacher.exe FUN_0059ca10` | 逐字段组装 JSON：`CtrlCode` → `sendState`(取 `DAT_007439f8`) → `tipInfo`(取 `DAT_007439e0`) → `serverIp`，末尾调 `FUN_005c7e10` |
| `Teacher.exe FUN_005c7e10` | 调 `FUN_005cbcf0(param_2, param_1)` 经**已建立连接对象**发送；**不硬编码端口**（端口封装在会话中） |

> 教师端反编译存档内**无硬编码 9003 常量**——端口来自连接/配置，与抓包"走 9003"一致。

### 5.2 学生端（接收 + 停止值）

| 函数 | 作用 |
|---|---|
| `MainLogic.dll FUN_100773f0` | 解析登录配置子记录：`assist_ip`/`controller_port`/`fileTransferPort`/`lockedAfterNetBroken`/`ioControlLevel`/`screenUdpVerityPort`/`transferType`…（对应 ③段配置） |
| `MainLogic.dll FUN_10077970`（`UnLoad`） | 退出清理时**回发** `CtrlCode = -0x44000000`（= `0xBC000000`）→ **正好是抓包停止值**，`0xBC` 高位代码实锤 |

### 5.3 关键旁证

- `CtrlCode`/`sendState`/`tipInfo` 字符串**仅出现于教师端 + MainLogic（退出回发）**；
- **学生端 StudentLogic.dll / Student.exe 不含 `CtrlCode` 字符串** → 学生端按**位置/偏移**解析子记录，非按 key 名匹配。
- `MainLogic.dll` 内无 `NetLimit`/`SpeedControl`/`OeNetLimit` 字符串 → 网络位执行落在 **OeNetLimit 驱动层**（见 [OeNetLimit_sys](../components/OeNetLimit/OeNetLimit_sys.md) 白名单+默认拒绝模型）。

## 六、证据强度

| 结论 | 强度 |
|---|---|
| 网络限制走 `tcp/9003`（非 8040 UDP） | 〔抓包 8040=0 + 代码经连接发送·铁证〕 |
| CtrlCode 必带 `0xBC` 高位 | 〔代码 `FUN_10077970` 硬编码 + 抓包实值·铁证〕 |
| 停止值 `0xBC000000` | 〔代码实锤·铁证〕 |
| 限制位 `0x00011111` 各比特语义 | 〔抓包位 + 02 号位定义·强，逐位落地需运行态〕 |
| 848 字节帧 = 40B 头 + JSON 子记录 | 〔抓包字节偏移·实测，中间字段语义推断〕 |
| `{"enable":1}` 帧 = 网络限制开关 | 〔推断，与 CtrlCode 帧并存〕 |

## 七、未决项（逐条闭环要求）

1. **学生端 CtrlCode → OeNetLimit 的精确调用链**：学生端无 CtrlCode 字符串，执行点为位置解析，需宽字符/偏移进一步定位或运行态挂钩，方能"逐位"坐实限制位语义。
2. **子记录 40 字节头中间字段语义**（序号/校验/类型/长度各占几字节）：需运行态或更多帧对照。
3. ~~**`{"enable":1}` 与 CtrlCode 帧的层级关系**：需抓"解除限制"时的对照帧（预期 `{"enable":0}` 或 `CtrlCode=0xBC000000`）。~~ **已闭环（9.22 抓包1 实测）**：解除 = 独立小帧 `{"CtrlCode":-1140850688}`（`0xBC000000`），无需 `enable:0`；下发后 7 s 新出网恢复，再限制 = 会话重建时补发完整 5 子帧限制包。见 [9.22 总览 §8](../9.22抓包/总览与结论.md)。
4. **JSON 编码混用规则**：哪些子记录用 UTF-8、哪些用 UTF-16LE，是否按 cmdType/子类型决定。
