# 31 · 学生端屏幕预览（缩略图上报）完整链路

> 主题：学生端主动上报屏幕缩略图 → 教师端课堂界面显示 64×64 预览
> 证据：tshark 抓包 22224 帧（`/analyze/抓包1/已过滤.pcapng`）+ `StudentLogic.dll` / `MainLogic.dll` objdump 机器码 + Ghidra 反编译
> 分析日期：2026-10-24
> **注意**：本文与教师端"屏幕广播"（7778 组播）是**两条完全不同的链路**，见 §五。

## 一、结论速览

| 项 | 实测结论 | 证据 |

**一句话**：学生端每 5 秒把整屏压缩成一张 64×64、约 1.2 KB 的 JPEG，用 `0x2B` 帧发到 9003；教师端按学生 ID 缓存并绘制成预览小图。**不经过 7778 组播，与屏幕广播无关。**

## 二、证据

### E-3101 抓包实证（0x2B 帧结构）

从 `已过滤.pcapng` 提取 `tcp.port==9003 && tcp.len>0`，按方向重组字节流后按帧头解析：

| 会话 | 0x2B 帧数 | 时长 | body 大小 | JPEG 尺寸 |
|---|---|---|---|---|
| `.57:52990 → .200:9003`（早期会话） | 22 | 114 s | 1085–1532 B | 64×64 ×22 |
| `.57:60110 → .200:9003`（主会话） | 109 | 541 s | 967–1499 B | 64×64 ×109 |
| `.200:9003 → .57`（反向） | 0 | — | — | — |

帧内字段（线上字节）：

```
total_len = 16 + body_len
cmdType   = 0x2B
u3        = 0x40 (64)   ← 缩略图边长
u4        = 0
body_len  = JPEG 字节数（约 1200）
payload   = FF D8 FF E0 ... FF D9
```

JPEG 头/尾统计（131 帧）：`ffd8ffe0` ×131、`ffd9` ×131 —— 全部为合法 JFIF，无截断帧。

### E-3102 时序（与心跳的关系）

教师 `0x59` 心跳间隔（132 帧）：**4.99 / 5.00 / 5.01 / 5.02 s**，严格 5 s。
学生 `0x2B` 间隔：**5.11 s** 中位数（偶有 4.09 s 补偿）。

「本帧 − 最近一次教师心跳」的差值在 0.07–1.33 s 间无规律漂移 → **两者是各自独立的 5 s 定时器，缩略图不由心跳触发**。

首帧时刻：登录配置帧到达 t=264.398，首张缩略图 t=269.272（+4.87 s）→ 定时器在登录阶段即启动。

### E-3103 学生端发送线程（`StudentLogic.dll` @ `0x1008d5b0`）

objdump 关键片段（地址为 VMA，基址 0x10000000）：

### E-3104 采集 → 缩放 → 编码链（`FUN_1007d650`）

```
FUN_1007d650(outBuf, &outLen, w, h, quality)
  FUN_1008cb70(...)                       // 屏幕抓取（GDI BitBlt 到 32bpp 缓冲）
  av_frame_alloc / avpicture_fill         // 源帧
  sws_getContext(srcW, srcH, fmt=0x1e, w, h, ...)   // ★ 缩放到 64×64
  sws_scale(...)                          // 整屏压成 64×64（非等比，画面会变形）
  构造 BMP 头：'BM'(0x4d42) / 头长 0x36 / 32bpp(0x20) / biHeight = -h（自顶向下）
  memcpy(BMP + 0x36, 像素, w*h*4)
  FUN_10073090 → Gdiplus "image/jpeg" 编码
      参数 quality = 0x28 = 40
      输出读回 outBuf（上限 0x600000）
```

要点：**先把整屏缩放到 64×64，再编码**，不是"截屏后裁剪"。

## 三、生命周期

```
学生登录完成（收到 0x2D/0x18/500/0x6F/0x1C）
        │
        ├─ SetTimer(hwnd, 2, 5000, timerProc)      // 5s 节拍
        │
        └─ 缩略图线程 FUN_1008d5b0:
             loop:
               若 stop 标志 → 退出
               若 无"出图"信号 → Sleep(1000) 继续等     // 1s 轮询
               抓屏 → sws_scale 到 64×64 → BMP → JPEG(q=40)
               组帧 0x2B(u3=64) → 送入 9003 发送队列
```

- 会话断开 → 线程退出，教师端该学生缩略图停止刷新并显示失败占位/灰态。
- 学生端**不等待教师确认**，教师也不对 `0x2B` 回任何帧（抓包确认）。

## 四、与"屏幕广播"的区分（关键）

用户强调"不要误以为是屏幕广播"，两者确实**完全不同**：

| 维度 | 屏幕预览（本文） | 屏幕广播（30 号文档） |
|---|---|---|
| 方向 | 学生 → 教师 | 教师 → 全体学生 |
| 通道 | **9003 TCP**（已建主连接） | **7778 UDP 组播** |
| 编码 | JPEG，64×64，q=40 | JPEG 或 **H.264**（x264） |
| 体积 | 约 1.2 KB/帧 | 1–7 MB/秒级 |
| 周期 | 5 s/帧 | 满帧率（20–25 fps） |
| 用途 | 教师课堂网格里的小预览图 | 全屏投影教学 |
| 参与进程 | `StudentLogic.dll`（发）/ `StudentScreenHelper.exe`（绘） | `ScreenSender.exe`（采编发）/ `MultiRender.exe`、`ScreenRender.exe`（收渲） |
| 是否经手教师端 MainLogic | 是（0x2B 分发） | 否（纯媒体进程） |

补充：学生端也能"自己开组播"（抓包3 中 `.58 → 229.1.1.58:7778` 推 H.264），那是"学生演示/被转播"场景，仍属广播族，不是预览。

## 五、伪端实现要点

### 5.1 伪学生端（向原版教师上报预览）

- 连接 9003、完成注册后，起独立定时器 **5000 ms**；
- 每拍：抓屏 → 缩放到 **64×64** → JPEG（质量 40 左右即可，原版为 40）；
- 发 `0x2B` 帧，`u3 = 64`，`u4 = 0`，`body = JPEG`；
- 不要等待回执；与 `0x59` 心跳互不干扰（各自 5 s）。

```python
import io
from PIL import Image, ImageGrab

def make_thumb(size=64, quality=40):
    img = ImageGrab.grab()          # 整屏
    img = img.resize((size, size))  # 非等比压缩，与原版一致
    buf = io.BytesIO()
    img.convert("RGB").save(buf, "JPEG", quality=quality)
    return buf.getvalue()

def send_thumb(sock, size=64):
    jpg = make_thumb(size)
    sock.sendall(encode_frame(0x2B, size, jpg))   # u3 = size
```

### 5.2 伪教师端（接收并显示预览）

- 在 9003 的会话循环里处理 `cmdType == 0x2B`：
  - `payload` 直接就是 JPEG，**不需要去掉任何头**；
  - 宽高 = `frame.u3`（原版恒为 64）；
  - 按学生 IP / 注册标识做 key 缓存，收到即替换；
  - 渲染失败（首帧前 / 断线）显示占位图（原版为 `GetThumbFail.png`）。
- 教师端**不需要**发任何"请求预览"的包；学生登录后自己就开始发。

```python
def on_frame(sock, f, thumbs):
    if f.cmd_type == 0x2B:
        size = f.u3 or 64
        thumbs[sock.getpeername()[0]] = (size, f.payload)   # 直接存 JPEG
```

### 5.3 已知可选项（未验证影响）

- 原版教师会在登录时下发 `0x5C`（空载荷）与后续 `0x5F`（带 0/1 标志）；`0x5F` 在学生端会把 `this+0x2F4` 置 1/0 并触发一系列 UI 动作。伪教师端**可以照发 `0x5C` 保持时序一致**，但不发也能收到 `0x2B`（抓包中 0x2B 由独立定时器驱动）。
