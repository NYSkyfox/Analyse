## 四、报文证据

### 4.1 广播可达范围

在 `192.168.1.x` 网段的学生机上，同时记录到两台教师机的 7777 广播：

```
192.168.1.200 → 255.255.255.255:7777   channel=4   (43 次)
192.168.0.200 → 255.255.255.255:7777   channel=2   (36 次)
```

→ `192.168.0.x` 网段教师端的广播同样到达了 `192.168.1.x` 网段的学生机。
→ 即：**受限广播 `255.255.255.255` 在两网段之间可达**（同一广播域或存在广播转发）。
→ 隔离不依赖 IP 网段，而由应用层 `channel` 字段承担。

### 4.2 组播地址规律

| 端口 | 组播地址 | 实例 |
|---|---|---|
| 7771 | `229.9.<网段>.<发送机 IP 末段>` | `1.200 → 229.9.1.200`；`0.200 → 229.9.0.200`；`1.7 → 229.9.1.7` |
| 7778 | `229.1.<网段>.200` | `1.200:8778 → 229.1.1.200:7778` |

### 4.3 教师端下发的参数配置 JSON（9003 通道）

`1.7` 向 `1.27:9003` 发送的报文（20 字节定长头 + JSON）：

```json
{
    "assist_ip" : "192.168.1.7",
    "controller_port" : 8040,
    "fileTransferPort" : 8555,
    "general_education" : 0,
    "home_work_server_ip" : "0.0.0.0",
    "ioControlLevel" : 0,
    "local_time" : "/2026/9/14/1/15/23/28/390/",
    "lockedAfterNetBroken" : 0,
    "screenUdpVerityPort" : 7788,
    "transferType" : "multicast",
    "waitseconds" : 80
}
```

**要点**

- `assist_ip`：教师端 IP；
- `controller_port`：**8040** —— 控制器端口（对应 `core.conf` 的 `UdpMessageControllerPort`），由本 JSON 下发给学生端；
- `local_time`：`/2026/9/14/1/15/23/28/390/`，即 **15:23:28**；
- 报文头部为 20 字节定长头（`71 01 00 00 2d 00 00 00 … 61 01 00 00`，随后紧跟 `{`）。

## 五、结论

1. **广播跨网段可达**：`255.255.255.255` 广播在两网段间互通，`192.168.1.x` 网段学生机可同时收到 `1.200` 与 `0.200` 两台教师端的 7777 广播。隔离仅由应用层 `channel` 字段实现。
2. **channel 为隔离依据**：教师端广播携带 `channel`，学生端按自身频道过滤；两者不一致时不互相认领。
3. **`1.200` 的数据在 ≈15:23:38 后终止**：其 7777 广播与 7771 心跳此后未再出现。受日志结束时间所限（15:23:34），未能覆盖终止后的完整时序。
4. **学生机可与新教师端建立连接**：`1.7` 开始发送 `teacher` 后 2~12 秒内，`1.25`、`1.35` 先后与其建立 9003 连接，`1.43` 随后向其上报 JPEG 数据。
5. **该过程不依赖 7777 广播**：`1.7` 全程未发送 7777 广播，仅使用 9003 主动连接与 7771 心跳即完成上述连接建立。
6. **8040 由教师端在连接建立时下发**：`controller_port = 8040` 出现在 9003 的配置 JSON 中。
7. **参数配置需重复下发**：学生机重启后为统一初始状态，教师端需重新下发配置（与 11 号报告的补发机制相互印证）。
