### 2. 【重大】学生端本地流量审查链实锤（LISSClient 组件群）
`LISSClient/` 文件夹 + 8045/9030 回环报文联合证明学生端存在**常驻本地流量嗅探 + HTTPS 解密 + 关键词审查**组件：
- `LISSNetInfoSniffer.exe  <学生IP> <MAC> [keywords.json]` 常驻启动（日志含 2026-09-22 16:54/16:56 两次启动，IP `192.168.1.57`，MAC `EC:D6:8A:F6:E9:F2`）；
- 加载 `C:\ProgramData\LISSClient\sslkey.log` —— **TLS 1.3 NSS 密钥日志格式**（`CLIENT_HANDSHAKE_TRAFFIC_SECRET …`），配合日志内 `TlsStreamDecryption::SetMMCNetKeywordFilePath` + `keywords.json`（"keywords count: 1"）→ **具备 HTTPS 解密 + 关键词命中审查能力**（实测日志中可见对搜狗/百度/WPS/手心输入法等 URL 的逐条记录与 "masking data" 处理）；
- 8045 回环新命令（抓包1 实测）：`{"filepath":"","ip":"192.168.1.57","mac":"EC:D6:8A:F6:E9:F2","type":"start-lissNet"}` = **启动 LISSNet 流量嗅探**；`{"type":"check-liss-sdk"}` 周期自检，响应恒为 `failed`（6 次）〔含义未决〕；
- 本批次 **9122（流量查询 API）= 0 帧**（抓包1 未过滤全量实测），与 9.20 不同：回环大流量改由"2MiB 全零块搬运"构成（见下条）。9122 的宿主即 LISSNetInfoSniffer 这一判断〔推断，依据 9.20 报文结构与本组件的流量查询职责〕，本批次未抓到其流量，不作为新证据。

### 3. 【重大】回环 1.46 GB 之谜：2MiB 全零块搬运
抓包1 未过滤回环段 42,449 帧中，22,345 帧大帧（>40KB）共 1.46 GB，全部落在 **1,388 个"相邻端口对"**（`50179↔50180`、`60547↔60548`…）：
- 每对生命周期内传 **32 段 × 65,495 B（= 65,535−40，最大 MSS 段）= 2,097,152 B = 2 MiB**，然后关闭，换下一对；
- 对内容逐字节核验（以 50179 对为样本）：**零 = 2,097,152，非零 = 0（100% 全零）**；
- 每次传输 ~1 ms 完成（32 帧挤在 0.5 ms 内）→ 非网络瓶颈，是**本地 socketpair 式快速拷贝**；
- 时间分布：抓包窗口内约每 3–5 分钟一波，持续整个 11.75 分钟。
**定性〔实测+推断〕**：学生端本地某组件以"新建 socket 对 → 写 2MiB 零块 → 关闭"方式做**大对象预分配/共享内存映射/缓存刷写的本地中转**（零块 = 稀疏分配特征，如 `ftruncate` 后 mmap、或显式 `write(0…)` 预热）。具体宿主进程与用途待结合 Ghidra（`OeNetLimit`/`MainLogic` 侧 `write` 2 MiB 常量定位）进一步坐实——**本批次未解决，列入未决项**。

### 8. 【重要】网络限制指令 9.20 vs 9.22 对照（CtrlCode 参数化实锤）

抓包1 中教师 `.200` 经 9003 下发了与 9.20 **同一体系**的限制指令，实测对照（9.20 值按 [23 号报告](../reverse-analysis/23_20260920_管控通道纠错实证.md) 记录，9.22 值为本批帧 6776/30263/34120 解码实测，Python 复核 `hex(-1140780783 & 0xffffffff) = 0xbc011111` 确认 9.20 记录无误）：

| 项 | 9.20（报告记录） | 9.22（本批实测） | 结论 |
|---|---|---|---|
| 限制值 CtrlCode | `-1140780783` = `0xBC011111` | `-1140850671` = `0xBC000011` | **限制位组合不同**：9.22 只有 bit0 网络 + bit4 应用，**无 bit8/12/16 三个 USB 位** |
| 停止值 CtrlCode | `0xBC000000` | `0xBC000000`（帧 30263） | 一致 |
| 停止值语义 | （9.20 未决项 3，未抓到解除帧） | **下发后 7 s 内新出网 SYN 恢复**（t=144.5→151.7） | **`0xBC000000` = 解除网络限制**，9.20 未决项 3 闭环 |
| tipInfo | "网页已经被拦截，请不要搜索限制内容!"（GBK） | 同文案（GBK） | 一致 |
| 帧结构 | 848B 登录帧含 4 条 40B 子记录 | 882B/723B 首连帧含 5 子帧（cmd 45/24/500/111/28，同构） | 同构（9.22 多 cmd 28 空载） |
| `{"enable":1}` 帧 | 有（UTF-16，+84/77s） | 有（帧 6776 子帧 2，UTF-16） | 一致 |
| 通道 | tcp/9003 | tcp/9003（会话 52990→60110） | 一致 |

**意义**：限制指令是**参数化**的——`0xBC` 高位 + `0xBC000000` 停止值为固定框架，限制位按教师端选择组合（9.20 禁网络+应用+USB，9.22 只禁网络+应用）。
**限制生命周期（抓包1 全窗口实测，详见 [抓包1 未过滤 §3.1](./抓包1_教师机192.168.1.200/未过滤.pcapng.md)）**：
`t=30.8s` 下发限制 → 113.7 s 内**零新出网 SYN**（已建连接 `150.171.110.133:443` 存活至 t=216s）→ `t=144.5s` 下发停止值 → 7 个新出网 SYN 全部握手成功（t=151.7–163.2）→ `t=162.8s` 新会话补发完整限制包 → 再封死至抓包结束。
→ **网络限制特征 = "拦截新建出网连接、放行已建立连接"**，且随限制/停止值实时翻转（**修正**：9.20 的"出网流量衰减"表述不精确）。

### 9. 【更正/澄清】
- **9122 本批 0 帧**：9.20 报告的"9122 = 学生端本地流量查询 API（loopback 1.7G 主因）"结论**不推翻**（该批次证据仍然成立），但**本批次 loopback 大流量主因不是 9122**，而是 §3 的 2MiB 全零块搬运。两种回环大流量形态在不同操作场景下出现。
- **10118 "126B 短连"** → 更正为 **60B SYN + 66B SYN-ACK 的空连接对**，无应用层数据。
- **7778 广播内容不唯一**：同一端口承载 JPEG（`.200` 教师机，9.20+本批）与 **H.264 视频**（本批 `.58` 学生自组播）两种媒体，按帧内容自适应，非固定格式。

## 五、未决项（逐条闭环要求）

1. **2MiB 全零块搬运的宿主进程与用途**（9.22 新增，最高优先）：需 Ghidra 定位学生端 `2*1024*1024` / `0x200000` 常量与 socketpair/mmap 序列；或下批次在搬运动作发生时加进程级抓包（Npcap 不支持 per-pid，用 ProcMon + 时间戳对齐）。
2. **学生控学生的"教师角色"入口**：`.58` 是如何启动"教师模式"的（同一学生端可切换角色？独立教师端程序？配置开关？）——需 `.58` 本机文件/进程证据（建议下批在 .58 抓回环+进程清单）。
3. **`check-liss-sdk` 恒 `failed` 的含义**：LISS SDK 缺失还是检测策略不通过？需 `LISSNetInfoSniffer` 侧 Ghidra 定位该字符串分支。
4. **9100 文件头帧完整结构**：首帧 `b8 00 00 00 | 00 00 00 00 | 68 09 ba 05 00 00 00 00 | a8 00 00 00 | 文件名…` 中，`0x05ba0968` = 95,550,888（文件长度）已坐实；`b8 00 00 00`（184）= 总长？`a8 00 00 00`（168）= 文件名长度+? 需多文件样本对照。
5. **7777 `checksum` 算法**：`channel=2` → 36301、`8` → 236307、`16` → 36761，疑似 `channel × K + 常量`（36301/2≈18150.5 非整数，K 待定），需第 4 个 channel（`192.168.1.200→4`）实测值联立求解。
6. **8041 鼠标消息全集**：本批仅见 `message:512`（移动），点击/滚轮（其他 message 值）未出现，需操作时补抓。
7. **10118 空连接的触发方**：学生端定时器还是教师端轮询触发（方向为学生发起 SYN，倾向学生端定时〔推断〕）。
8. **回环 567 端口会话**（1,270 帧/155KB 持续型）内容未深解——与 9.20 脚本里"8045 监听侧"是否同一体系待确认。
9. **学生端"教师模式"对真教师 .200 的干扰**：.57 双挂载时，.200 与 .58 同时下发管控会如何仲裁（未在本批出现）。
10. **9.22 未禁 USB（`0xBC000011` vs 9.20 `0xBC011111`）是教师端操作选择还是策略差异**：本批限制值无 bit8/12/16 三个 USB 位；教师端 `ioControlLevel`/限制组合的生成逻辑待代码层对照（`Teacher.exe FUN_0059ca10` 的 `DAT_007439f8` 来源）。
11. **抓包3 中 `.57` 出网被拦的指令来源**：`.58` 仅下发 `0xBC000000` 停止值，但 `.57` 出网 443 SYN 无应答——推断限制仍来自真教师 `.200`（会话未断、双挂载），待 .58/.57 双端同抓验证。
