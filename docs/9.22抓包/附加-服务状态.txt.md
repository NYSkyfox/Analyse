## 三、与既有分析的对应（交叉印证）
1. **`oenetlimit`（内核驱动）** = 网络限制执行层。9.20 已定性其"白名单+默认拒绝"模型（见 `OeNetLimit_sys` 报告）；本批抓包3 中 `.57` 出网 443 握手被拦（`20.190.148.162`/`4.145.79.82` SYN 无响应）与该驱动 RUNNING 状态一致 → **9.22 时网络限制处于生效态**；
2. **`mmpc`** = Os-Easy 学生端主服务（多播教学客户端核心进程），WIN32_OWN_PROCESS 且 ACCEPTS_SHUTDOWN（优雅退出，与 9003 会话退出时回发 `CtrlCode=0xBC000000` 的 UnLoad 行为对应）；
3. **`easyusbflt`（内核驱动）** = USB 存储过滤层（CtrlCode `0x00011111` 中 bit8/12/16 三个 USB 位的执行点）；
4. 三服务同时 RUNNING 是**完整管控态**的标志：网络（oenetlimit）+ 主机（mmpc）+ USB（easyusbflt）三层执行器全部在线。

## 四、结论
本文件为学生机管控态的"服务面快照"，与 9.22 两批抓包的"流量面"相互印证：
 - 抓包1（16:53–17:05）：网络限制经历"限制（16:54:24）→ 解除（16:56:21）→ 再限制（16:56:36）"完整周期（见 [抓包1 未过滤 §3.1](./抓包1_教师机192.168.1.200/未过滤.pcapng.md)）↔ oenetlimit RUNNING；
- 抓包3（17:35–17:40）：出网仍被拦 ↔ oenetlimit 仍 RUNNING；
- 学生控学生测试中 `.57` 的管控状态**未被 `.58` 改变**（`.58` 只下发了 `0xBC000000` 停止基线，未下发限制位）——即"接管"与"网络限制"是两个独立控制面。
