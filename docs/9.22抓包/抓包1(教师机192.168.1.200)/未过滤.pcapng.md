### 3. 2MiB 全零块搬运（本文件最大发现，逐字节实证）

**统计（全量实测）**：
- 1,388 个"相邻端口对"（`50179↔50180`、`50181↔50182`、`50186↔50187`、`60547↔60548`…，端口号不连续、成对出现）；
- 每对传输 **32 段 × 65,495 B = 2,097,152 B = 2 MiB**（65,495 = 65,535 − 40，恰为 IPv4+TCP 最大 MSS 段），然后 FIN 关闭；
- 总 22,345 大帧 / 1,463,485,775 B ≈ **1.33 GiB**，占文件 99.5%；
- 单对传输耗时 ~0.5–1 ms（32 帧挤在一个毫秒内）；
- 时间分布：整个 705 s 窗口内约每 3–5 分钟一波（首波 16:55:55.06，末波 17:05:18.34），共 1,388 对。

**内容核验（样本 `50179↔50180`，全 32 段 2,097,152 B 逐字节统计）**：
```
零字节 = 2,097,152   非零字节 = 0   → 100% 全零
```

**定性〔实测+推断〕**：学生端本地某组件周期性执行"新建 TCP 端口对 → 向对端 socket 写 2 MiB 零块 → 关闭"。
特征指向**大对象本地中转/预分配**（零块 = 稀疏/清零缓冲，socketpair 式快速拷贝，无网络延迟）。
可能宿主〔推断，待 Ghidra 坐实〕：OeNetLimit 驱动配套用户态组件的流量缓冲、LISSNetInfoSniffer 的抓包缓存、或 mmpc 的共享内存预热。
**闭环要求**：Ghidra 中定位 `0x200000`/`2*1024*1024` 常量 + `socketpair`/`socket(AF_INET, loopback)` 序列（未决项 1）。

**关键结论〔实测〕**：
1. **网络限制只拦截新建出网连接，已建立 TCP 连接不受影响**（限制期 150.171.110.133:443 存活 175+ s）——印证 OeNetLimit"白名单+默认拒绝"模型对新/旧连接的处理差异；
2. **`0xBC000000` 停止值帧 = "解除网络限制"指令**：下发后 7 s 内新出网恢复（t=144.54 → t=151.67），闭环了 9.20 报告未决项 3（预期"解除限制时出现 CtrlCode=0xBC000000"）；
3. 本文件完整记录了一个**"限制 → 解除 → 再限制"周期**：两轮的 9030/8045 IPC（`set-teaAndStu-ip`/`start-lissNet`/`check-liss-sdk`）与 9003 会话重建（52990 → 60110）均与限制指令一一对应；
4. 9.20 的"限制后出网流量衰减"表述**不精确**——正确特征为"**新出网连接封死 + 存量连接放行**"，且封死与否随 CtrlCode 值（限制/停止）实时翻转。
